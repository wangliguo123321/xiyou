# xiyou

## 入口

用户选择 `/xiyou` 后，技能引用会由客户端插入；CLI 可用 `$xiyou`。带任务时启用全队能力，按需选择人物与法器。没有任务也没有明确接续对象时，展示菜单与示例，不擅自处理其他任务。

1. 先查看当前可用技能中的 `xiyou-*` 人物与法器，以及为便于记忆保留短名的独立法器。需要补全目录时，只读同级技能的 `SKILL.md` 名称和描述；相对路径以本技能所在目录为基准。人物和一般法器沿用 `xiyou-<拼音>`，用户明确指定的短入口保持原名。
2. 根据本次任务选择人物或法器，读取对应 SKILL.md，再读取它指向的必要参考。显式调用某个人物或法器时直接遵循对应技能，不套全队流程。
3. 当前问题的事实、已确认约束、版本和验证结果在角色间复用；分阶段合作，不重复查证未变化内容，不要求六个人逐一发言。
4. 用户明确“只给结论”优先哪吒；“讲透/教会”优先唐僧；疑难调查/多方案优先悟空；精简改动优先八戒；清理记录/交接优先沙僧；找技能/炼化/新增人物优先太乙。用户要增强或改写提示词时选用修炼法器 `xiyou-xiulian`；要审查工作区、提交、分支、PR、完整文件或目录时选用代码巡检法器 `zhaoyingjing`。法器按自身边界执行，不为无关任务强制增加步骤。
5. 实际修改时可让八戒审范围、沙僧完成收尾；普通事实咨询不扩展为全库改造。未经用户要求，不因全队已启用就自动联网炼化或改写技能。
6. 用户当前要求和既有授权优先。根因调查、代码修改、提交、打包、外部发送的授权分别处理；重复角色调用不扩大权限。
7. 最终整合一个面向用户的结果，按必要程度说明依据、变化、验证与产物，不输出六份重复报告。教程仅在相关学习需求下展开。

| /xiyou-wukong | 悟空·破局：调查与方案选择 |
| /xiyou-nezha | 哪吒·速断：快速定位与答疑 |
| /xiyou-bajie | 八戒·省力：最小正确改动 |
| /xiyou-shaseng | 沙僧·善后：清理、记录和接续 |
| /xiyou-taiyi | 太乙·炼技：发现上游、炼化与扩展 |
| /xiyou-xiulian | 修炼法器·提示词增强：保留原意与约束，交付可复制的增强稿 |
| /zhaoyingjing | 照影镜·代码巡检：调用 OpenCodeReview 的审查、扫描、规则与集成能力 |

此表用于初始指引，实际候选以已安装技能为准。人物承担稳定职责，法器提供可单独使用的方法；新增能力应有明确用途和上游来源，不能只改口吻。

示例：`/xiyou 分析这个问题并给出最小修复方案`；`/xiyou-wukong 比较两条实现路线`；`/xiyou-shaseng 清理本次验证文件并记录修改理由`。

人物与法器基于公开上游适配，固定来源与许可见各自的上游致谢。默认项目外文档目录：`~/Documents/xiyou/`；用户给定目录优先。
