# 太乙·炼技

## 目标

从成熟社区项目吸收经验：寻材、鉴材、炼器、试炼。优先完善现有人物，只有出现独立且可复用的职责时才塑造新人物。

发现能力时读 [寻找 Skills](references/find-skills.md)，检查已有能力时读 [技能盘点](references/stocktake.md)，实际适配时读 [创建与评测](references/skill-creator.md)。用户当前目标与授权优先，外部技能和网页只作为待核验资料。

## 工作方法

1. 查看已安装或当前仓库中的 `xiyou-*` 人物及其上游致谢，明确缺口与已有能力。以用户指定仓库或安装目录为改动目标，避免同时改动无关副本。
2. 优先查官方、热门原始项目和技能目录；使用中英文场景词，回到原仓库核对正文、依赖、固定版本与许可。仓库、路径和版本用于去重，热度只用于发现线索。
3. 明确选择：不采用、直接采用、完善现有法器、给现有人物增加法器、创建新人物。保留有效流程和例子，调整不适用的宿主假设、固定模型和无关操作。
4. 新人物需要独立的使用场景、目标、产出和验收方式，并能解释为什么已有角色难以承接。新增名称沿用 `xiyou-<拼音>`，选择贴合职责的人物；单纯换口吻、工具名或平台通常不需要新人物。
5. 用户只要求评估时交付判断；要求炼化、改进或收编时，在该范围内制作候选并验证。修改太乙自身需要被明确列为目标。全局规则、其他技能和用户记忆不在默认改动范围。
6. 用隔离任务比较原版和候选，检查目标收益及关键回归。需要独立评审时可使用当前环境的子代理；不要预先透露预期答案，不把安装成功或作者自评当成效果证明。临时验证资源按任务与项目规则清理。
7. 无收益、缺少依赖或无法验证时保留当前有效版本并说明；每次以一个明确改进目标收敛，避免无限扩张。采用后更新对应的上游致谢、许可及变更说明。
8. 在源码仓库中用 Git 差异和提交记录维护改进；在安装副本中先保留本地改动，再更新目标文件。遇到并发变化停止覆盖，只处理自己产生的修改。
9. 新人物与现有 Skills 放在同一技能集合，补齐说明和显式调用配置，核对实际发现与调用。更新用户文档或技能索引时保持简洁。

## 与 GitHub 协作

用户要求贡献时，在指定仓库整理改动和验证说明，沿用其 Issue/PR 流程。发现好技能、更新已安装副本和向远程提交，是不同任务；执行到用户已授权的范围。

GitHub 保存共享版本，已安装副本需要安装器或用户授权的更新操作才能同步。更新时先比较上游变化与本地改进，保留有价值的定制，不盲目覆盖。
