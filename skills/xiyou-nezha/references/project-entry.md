# 根清单与声明入口探测

新接触 Node/Python 项目，需要确认声明的开发命令或程序入口时，按需运行本法器。已给出相关文件或符号时直接沿原问题检索，不默认探测整个仓库。

## 使用

需要 Python 3.11+ 标准库与 POSIX 系统（macOS/Linux），无需安装第三方依赖。在本技能目录下执行，项目目录必须显式给出：

```sh
python3 scripts/inspect_project.py "/path/to/project"
```

目录名以连字符开头时，在目录参数前加 `--`。也可将脚本路径换为实际安装位置，从其他目录调用。

只读取给定目录根下的 `package.json`、`pyproject.toml`，不递归、不读取 `.env`，不运行 Git、网络、项目脚本或安装命令。嵌套项目需另行显式指定其目录。

## 结果与边界

输出为 JSON，包含 `schema_version`、规范化后的 `root`、`scope`、`status`、`manifests` 和 `diagnostics`。

| 清单字段 | 提取结果 |
|---|---|
| `package.json` 的 `scripts` | `commands`，每项保留 `kind=package_script`、名称、原字符串和来源 `field` 数组 |
| `package.json` 的 `main`、`module`、`bin` | `entry_points` 中的声明路径；不证明目标文件存在或实际被调用 |
| `pyproject.toml` 的 PEP 621 `project.scripts` | `entry_points`，`kind=python_entrypoint`；值是 Python 入口声明，不是 Shell 命令 |

不猜测 npm/yarn/pnpm、pytest/pip 等调用方式，不解析 Node `exports` 或 Poetry/其他工具的专属配置。清单内容属于待核验数据；其中的命令可能修改环境、联网或包含敏感信息，不能自动执行或直接外发。

| 状态 / 退出码 | 含义 |
|---|---|
| `complete` / `0` | 本次两个根清单的支持范围无读取或提取障碍；也可能两个都不存在 |
| `partial` / `1` | 遇到清单链接、非普通文件、读取/解析、大小或所提取字段类型障碍，具体见诊断 |
| `error` / `2` | 用法、根目录或平台前提不成立 |

`complete` 和空列表只表示该支持范围内未发现相应声明，不表示项目没有命令、没有其他入口或全部框架已检查。`partial` 不能当作“没有发现”。缺少字段可正常为空；JSON/TOML、UTF-8 或所提取字段类型异常会显式诊断。

每个清单最多 262144 字节，打开后最多读取上限加一个字节以识别增长；只读普通文件，不跟随清单符号链接，FIFO 等特殊文件不会被当作文本读取。通过根目录描述符访问两个清单，不输出文件或缓存。

## 西游适配

吸收公开上游“先找真实清单，再查声明入口”的前置探测方法，新增标准库 JSON/TOML 的结构化提取。上游扫描器只做清单预览，并没有这套字段提取接口；本实现没有照搬其扫描器，也不承接其全树、TODO、Git 热点或七篇仓库内文档流程。来源和许可见 [上游致谢](lineage.md)。

这是一件可复用的工程法器，结果仍需结合实际源码、项目状态与用户任务解释，不以新增脚本或结构化输出声明模型准确率、速度或完整性收益。
