# 场景指南

仅在对应场景需要时采用这些检查项。示例展示取舍，不是每次都要填完的模板。

| 场景 | 优先补清 | 避免擅自加入 |
|---|---|---|
| 开发与修改 | 期望行为、已有工程约束、改动范围、验证方法 | 新框架、重构、发布、未经要求的功能 |
| 排查异常 | 复现条件、实际与预期、已有日志、原因的证据 | 在调查前认定根因、未经要求直接修复 |
| 写作与内容 | 已知受众、用途、材料、篇幅和语气 | 虚构经历、数据、引文和效果承诺 |
| 检索与调研 | 问题范围、时间范围、来源依据、比较维度 | 把待查结论当前提、编造引用 |
| Agent / 系统提示词 | 职责、输入输出、工具边界、失败处理 | 更高指令权限、凭空增加工具、展开隐藏推理 |

## 粗略需求 → 可验收的任务

原文：

> 帮我看看这个登录为什么失败，先不要改代码。

可增强为：

```text
排查当前项目的登录失败原因，先不要修改代码。根据已有错误信息、复现步骤和相关实现，区分已确认事实与待验证假设；给出最可能的原因、证据和下一步最小验证方法。若缺少关键现场信息，明确需要补充的具体内容，不直接认定根因。
```

“排查”得到可检查的产出；“先不要改代码”保留。不预设网络、鉴权或缓存是原因。

## 相关上下文 → 消除指代

已知上下文：Vue 3 现有后台；仅需按已选状态筛选列表；不新增依赖。原文：

> 把刚才说的筛选做一下。

可增强为：

```text
在现有 Vue 3 后台中实现按已选状态筛选列表，沿用项目当前的状态和列表处理方式，不新增依赖。检查不同状态和清空筛选时的列表结果，并说明实际验证情况。
```

不能因为“筛选”就增加关键词搜索、多选、导出或新的状态管理库。上下文没有说明的字段名和接口留待实现时核查。

## 已有严格提示词 → 保真精简

原文：

> Please inspect `src/auth.ts`. Do not edit files. You may use `rg`. Return JSON with exactly `cause` and `evidence`; if uncertain set `cause` to null.

可增强为：

```text
Inspect `src/auth.ts` without editing files. You may use `rg`. Return only JSON with exactly two keys: `cause` and `evidence`. Set `cause` to null if the cause is uncertain.
```

不把可用的 `rg` 改成必用，不改文件路径、键名或 null 的语义，不添加第三个 JSON 字段。

## 缺少事实 → 保留空位

原文：

> 帮我写产品介绍，不要问我问题。

可增强为：

```text
根据以下材料撰写产品介绍：
产品与真实特点：【待补充：产品名称、用途和已确认特点】
面向读者与使用场景：【待补充：读者、发布位置】
突出材料中能支持的价值，表达清楚自然，不编造数据或效果。若材料仍有缺口，保留对应占位，不追问。
```

不编造产品类型或默认目标受众。用户明确需要可立即使用且不含占位符的版本时，可把“先从用户提供的产品材料提取名称、用途、特点”等输入处理写进下游任务。
