# 结论与证据对应

> 基于公开上游的中文适配；来源、固定版本和许可证见 [上游致谢](lineage.md)。

## 确定主张 → 获取证据 → 读取结果 → 限定结论

每个完成主张需要对应的可观察结果。先确定什么能证明它，执行适当验证或复用仍对应当前代码状态的结果，检查完整输出、退出状态及覆盖范围，再下结论。

| 主张 | 所需证据 |
|---|---|
| 文件修改完成 | 实际文件与差异 |
| 编译成功 | 对应代码版本的构建结果 |
| 原问题解决 | 原场景或有代表性的行为验证 |
| 需求满足 | 对照要求及相关验证 |
| 构建包可交付 | 实际构建、包标识、有效链接与来源 |
| 设备验收 | 对应设备、环境、版本及反馈 |

子代理报告也需要结合产物与证据核对。部分检查证明的范围如实保留，不能向未覆盖部分推广。验证失败就记录失败，不能使用模糊措辞暗示已经成功。

## 西游适配

继承证据先于主张，不照搬“每次说话必须重新运行所有检查”。源码与条件未变化可复用有效证据；材料过期或目标变化时补验。临时验证资源及时清理。缺少设备时报告编译通过、设备待验，而非假装全过或抹去已经完成的工作。
