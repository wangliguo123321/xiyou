# 视频采样帧证据

用于已有本地 MP4/MOV 的交付验收：核对明确的时长约定、在指定时点附近查看真实解码画面。它生成证据，不负责制作/编辑视频，也不宣称整段内容、声音或交互合格。

## 方法

1. 明确要核哪份视频、哪些场景和采样时点，以及预期画面。场景有明确区间时优先选其中点；怀疑转场缺陷时在前后分别取样。不能只看联系表就判断细节合格。
2. 复用已有工具取得同等证据；需要可分发的轻依赖接口时，调用下列脚本。它使用实际输入内容快照，绑定视频流声明时长、请求点、实际解码 PTS 和 PNG 身份。
3. 实际逐图查看：核文字、缺失内容、重叠/裁切、冻结或预期顺序。需要判断连续运动、音轨或播放交互时另做相应验证，不能从几个静态采样外推整段通过。
4. 分别说明“工具完成采样”“时长符合明确约定”“所看帧的内容合格”及未覆盖范围。清单中的 `visual_review` 固定为 `not_performed`，实际看图结论由执行者另记，不能自动改成合格。
5. 正式交付证据按用户指定位置保留。若仅本次临时验证，先保存最小事实/哈希和结论，再清理明确归属本次的输入快照及图像，保留用户原视频和既有目录。

## 接口

Python 3.9+ 标准库及已安装、在 PATH 的 `ffmpeg` / `ffprobe`，不自动安装：

```bash
python3 scripts/inspect_video_frames.py --input /path/to/demo.mp4 --times 0.2,1.6,3.2 --output-dir /path/to/new-evidence --expected-duration 4 --duration-tolerance 0.05
```

路径相对本技能目录。预期时长与容差由当前任务约定；不做时长符合性判断时同时省略这两个参数。输入必须是本地普通文件；输出父目录需存在，目标目录必须全新。已有目录、文件或符号链接不覆盖，也不混入旧 PNG。

- 每次显式选择 1–10 个有限非负秒数，保持请求顺序；每点必须小于所选视频流声明时长。不自动采样“全片”或把 0 个样本当完成。
- 仅支持 MP4/MOV 的首路视频流、明确正时长及从零开始的时间轴。元数据缺失/歧义或不支持的时间轴会拒绝；不把未知当零。文件不含视频也会拒绝。
- 每点选择**实际解码 PTS 大于或等于请求点的第一帧**，保留真实整数 PTS、时间基和对应 PNG；不用帧率推算实际时间。变帧率下，实际时点可能晚于请求点。即使请求仍小于声明时长，片尾也可能没有符合条件的后继帧，此时拒绝，不能把旧图或上一帧充数。
- 输入至多 64MiB，视频流声明时长至多 120 秒，单帧至多 8,294,400 像素，PNG 至多 32MiB；单条工具至多 20 秒、总计至多 120 秒。这些是本接口资源边界，不是视频质量标准。
- 失败会给出诊断，不报证据齐备；清理本次已创建的部分输出，保留用户已有内容。支持范围以实际工具与输入为准；解码成功不保证文件所有片段都可解码或容器声明完全真实。

输出为原生解码 PNG 和清单，关联输入内容摘要、工具身份、声明时长、预期对照、请求与实际帧时间、尺寸及帧摘要。清单用于定位和复核，仍须打开 PNG 看实际像素。抽帧按编码尺寸并关闭自动旋转，带旋转标记的播放方向需另核。它不运行浏览器、原始项目或网页，不下载或执行媒体内引用的程序。
