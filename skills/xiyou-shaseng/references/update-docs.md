# 依据真实产物更新文档

> 源码驱动更新继承自 ECC `update-docs`；组织方式借鉴 Matt Pocock `writing-for-agents`。来源、固定版本和许可证见 [上游致谢](lineage.md)。

## 找到事实来源

根据任务选源码、实际差异、构建脚本、接口定义、提交、日志和验收结果作为来源。字段、命令、版本与行为从这些材料取得，不能凭模板编造。

## 更新对应内容

只更新受当前变化影响的记录，保留用户手写部分。将源码决定、版本或命令与文档相关段落对应；检查已有文档是否被代码变化影响，时间长只是检查线索，不能单凭年龄认定过期。

## 核对与汇报

保存后回读，核对状态、路径、链接、版本和未完成事项。汇报更新、保留、受阻的部分。重要命令只保留与当前任务有关的内容。

## 让下一次使用者知道何时读、何时算完成

- **记录不容易重新查到的理由。** 保留为什么选这个位置和范围、放弃某路线的条件；能从源码或产物直接取得的事实，用版本和链接定位，避免复制成易过期的第二份事实。
- **同一事实维护一处。** 已有规格、方案、任务记录承载相同内容时，更新其对应位置或引用它；不同用途的文档通过链接接续，保护人工段落。
- **资料入口写明用途与触发条件。** 例如“设备复现时读环境记录”“调整超时时读兼容约束”。常用事实放在主记录，特定场景细节按需引用，避免孤立资料没人知道何时读取。
- **下一步带可观察的完成条件。** 写清应核对什么结果、在哪里取证，以及达到什么状态才能继续；事实缺失时保留缺口，不虚构负责人和期限。

完成条件：接手者能从主记录定位当前状态、决策理由、证据和下一步；链接可用且适用于标注版本；已有人工内容完整保留。内容足够接续即可，不为每次任务创建一套文档体系。

## 西游适配

上游默认 CONTRIBUTING/RUNBOOK/环境文档流程改为项目外任务记录，保留事实来源驱动、人工内容保护和变更影响检查。吸收完成条件、资料入口与单一事实来源，不继承额外文档层级、宿主技能调用或全局指令改写。核心记录增加“为什么这样改、为何这个范围、验证到哪一步”。不自动遍历配置或重建无关文档，不把业务仓库 docs 当默认输出位置。
