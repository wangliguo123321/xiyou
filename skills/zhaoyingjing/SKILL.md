# 照影镜·代码巡检

## 目标

把 OpenCodeReview（OCR）的完整能力收进一个好记的入口。用户描述想审什么，不需要记 `ocr` 参数；本技能选择执行方式、补齐业务背景、运行审查，并把覆盖范围、发现和失败边界整理清楚。

用户当前要求和项目约定优先。普通“审查”只报告；明确要求“审查并修复”才修改代码。提交、推送、发布和 CI 配置分别按用户授权处理。

## 选择能力

先根据任务选择模式，再只读 [OCR 操作指南](references/ocr-operations.md) 中对应章节：

- 当前工作区、某个提交、分支或本地 PR 差异：使用 **差异审查**。
- 没有可用 diff、要检查目录或陌生代码库：使用 **全量扫描**。
- 希望当前 Agent 负责判断，或不想配置 OCR 的模型端点：使用 **委托审查**。
- 希望 OCR 使用独立模型复核、输出 JSON/SARIF 或接入自动化：使用 **OCR 自管审查**。
- 要新增、核对或排查项目规则：使用 **规则与排除**。
- 要继续中断任务、查看历史或回放结果：使用 **会话与恢复**。
- 要切换提供商、调整投入/预算、自定义工具、接外部 MCP 或启用 OpenTelemetry：使用 **配置与扩展**。
- 要接入代码托管平台、CI 或编码 Agent：使用 **集成与 CI**。

未指定时：普通代码审查优先使用 OCR 自管审查；OCR 尚未配置模型、用户希望复用当前 Agent，或环境不适合外发给第二个模型时，改用委托审查。先说明实际选择及数据将经过哪里。

## 统一流程

1. 明确目标：工作区、提交、分支范围、PR 对应本地范围或扫描路径；从用户说明、提交信息和相关文档提炼简短业务背景。没有可靠基线时不要猜主分支。
2. 准备 CLI：确认 `ocr` 可运行并记录版本。若命令不存在，解释将安装的官方包；执行型请求可把官方 CLI 安装作为必要准备继续完成，受限环境则给出安装命令和阻塞点。只有用户要求更新或现有版本缺少所需能力时才升级，不静默改为 `latest`。
3. 准备所选模式：委托模式不需要 OCR 模型配置；OCR 自管模式运行 `ocr llm test`，缺少配置时引导用户在本地完成交互设置，不索取、回显或把密钥写入聊天或仓库。
4. 运行所选 `ocr` 命令并冻结审查范围。逐项记录已审、跳过和失败；未跟踪文件、排除规则、预算、超大文件、超时和子任务失败都要进入覆盖摘要。不能只凭退出码判断完整成功。
5. 按实际 diff 和必要上下文复核发现。每条问题给出路径、准确行号或明确的定位失败、严重度、类别、触发条件、影响和建议；过滤缺少证据的低价值提示。
6. 输出关键发现和覆盖状态。没有高/中风险发现时，只说明本次范围内未发现对应等级问题，不宣称代码完全安全。
7. 用户明确要求修复时，只处理已确认且范围清楚的问题，运行相关验证，并重新审查受影响差异；不要自动提交或推送。

## 版本与更新

上游来源、当前炼化基线、许可证和更新检查点见 [上游致谢](references/lineage.md)。维护或升级本技能时，先核对上游两个官方 Skill、CLI 帮助、发布说明和文档，再更新本技能的路由与兼容说明；不要只替换版本号。西游总入口仍可路由到本技能，但用户可直接记忆和调用 `/zhaoyingjing` 或 `$zhaoyingjing`。

OCR 的参数以当前安装版本的 `ocr <command> --help` 为准。操作指南保存稳定的意图映射和关键陷阱，不复制完整 CLI 手册。
